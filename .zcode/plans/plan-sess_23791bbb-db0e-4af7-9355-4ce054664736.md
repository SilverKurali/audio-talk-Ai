## Windows 支持实施计划

### 概述
audio-talk-ai (ATA) 是 just-talk-go (JT) 的分支。JT 已有完整的 Windows 支持（使用 `golang.org/x/sys/windows`，无 CGO）。ATA 目前有部分 Windows 文件（热键提供程序、录音机），但剪贴板、自动上屏、诊断、叠加层和配置路径均不完整或有编译错误。

### 要修改的文件（按实施顺序）

---

#### 1. 修复剪贴板 — 编译错误
**文件：** `internal/clipboard/clipboard_windows.go`（新建）+ `internal/clipboard/clipboard_cmd.go`（修改构建标签）

**问题：** `clipboard_cmd.go`（构建标签 `linux || windows`）引用 `candidates()`，该函数仅在 `clipboard_linux.go`（`linux`）中定义。Windows 构建失败。

**修复：**
- 新建 `clipboard_windows.go`，使用 `atotto/clipboard` 库（已在 go.sum 中作为间接依赖）实现 `newPlatformClipboard()`
- 将 `clipboard_cmd.go` 的构建标签从 `linux || windows` 改为仅 `linux`

---

#### 2. 修复会话包 — 编译错误
**文件：** `internal/session/server.go`（添加构建标签 `//go:build !windows`）

**问题：** `server.go` 使用 `github.com/creack/pty` 和 `syscall.SysProcAttr{Setsid: true, Setctty: true}`，在 Windows 上不可用。

**修复：** 添加 `//go:build !windows` 构建标签。会话（detachable TUI）是可选功能，Windows 不需要。

---

#### 3. 修复 main.go — Unix 特定问题
**文件：** `cmd/audio-talk-ai/main.go`

多个问题需要修复：
- **`/tmp/` 日志路径**（第 197、204 行）→ 使用 `filepath.Join(os.TempDir(), "audio-talk-ai.log")`
- **`syscall.Flock`**（第 546、555 行）→ 替换为基于 `os.OpenFile` + `O_CREATE|O_EXCL` 的跨平台文件锁定
- **`SysProcAttr{Setsid: true}`**（第 376 行）→ 用 `//go:build !windows` 保护或添加运行时检查
- **`printTroubleshooting()`**（第 419 行）→ 添加 Windows 故障排除行："Windows: 检查麦克风隐私设置"
- **`installSelf()`**（第 426 行）→ Windows 安装到 `LOCALAPPDATA\Programs\audio-talk-ai\`
- **`stateDir()`**（第 525 行）→ Windows 上使用 `os.UserCacheDir()`
- **`lockPath()`**（第 533 行）→ Windows 上使用 `os.TempDir()`
- **`samePath()`**（第 489 行）→ Windows 上添加 `strings.EqualFold` 不区分大小写比较

---

#### 4. 修复配置路径
**文件：** `config/config.go`

`FindConfig()` 和 `keyDir()` 使用 `~/.config/audio-talk-ai/`。Windows 上应使用 `os.UserConfigDir()` 获取 `%APPDATA%/audio-talk-ai/`。

---

#### 5. 实现自动上屏
**文件：** `internal/autotype/autotype_windows.go`

`pastePlatform()` 当前返回 `"not implemented"`。`simulatePaste()` 已编写但未使用。

**修复：** 实现 `pastePlatform()` — 先写入剪贴板，等待 50ms，然后调用 `simulatePaste()` 发送 Ctrl+V。与 JT 的 `autotype_windows.go` 相同，但使用 ATA 的剪贴板包路径。

---

#### 6. 创建 Windows 诊断
**文件：** `internal/doctor/doctor_windows.go`（新建）

`doctor_other.go` 返回 `Healthy() = false` 并显示 `"windows 暂未实现"`，阻止启动。

**修复：** 新建 `doctor_windows.go` 检查：
- 全局热键 — 始终可用
- 麦克风录音 — 检查 `ffmpeg`/`sox` 是否可执行，以及 `waveInGetNumDevs` > 0
- 剪贴板与自动上屏 — 始终可用
- ASR 配置 — 检查 ATA 的多提供程序 ASR 配置模型

---

#### 7. 移植叠加层
**文件：** `plugins/overlay/backend_windows.go`（新建，从 JT 移植）

从 JT 移植完整的 `backend_windows.go`（约 800 行 Win32 代码），实现：
- 使用 `CreateWindowExW` + `WS_EX_LAYERED`/`WS_EX_TRANSPARENT`/`WS_EX_TOPMOST` 创建原生 Win32 叠加窗口
- 使用 `CreateDIBSection` + `UpdateLayeredWindow` 进行位图渲染
- 圆角矩形、阴影、波形动画、文本渲染
- 支持 `top-left`、`top-center`、`bottom-left`、`bottom-center`、`bottom-right` 位置
- 标签映射：CON→LINK、STP→STOP、WAI→WAIT、ERR→ERR、IDL→IDLE

需要修改模块路径（JT 的 `github.com/c/just-talk-go` → `gitee.com/AY77-OP/audio-talk-ai`）和配置引用。

---

#### 8. go.mod 维护
**文件：** `go.mod`

将 `github.com/atotto/clipboard` 从 `// indirect` 提升为直接依赖。

---

### 依赖关系

```
剪贴板 → 编译成功
  ↓
会话包 → 编译成功
  ↓
main.go → 编译成功，配置路径正确
  ↓
自动上屏 → 功能完整
  ↓
诊断 → 应用可启动
  ↓
叠加层 → 视觉完整
```

### 不需要修改的文件
- `hotkey/provider_windows.go` — 已完整实现（WH_KEYBOARD_LL 钩子 + GetAsyncKeyState 轮询）
- `plugins/voice/recorder_windows.go` — 已完整实现（ffmpeg/sox 子进程）
- 所有 `asr/` 包 — 纯 HTTP/WebSocket，跨平台
- `engine/` 包 — 完全可移植
- `internal/tui/`、`internal/webui/` — 可移植
- `config/crypto.go` — 纯标准库，可移植
