三个子包共享同一套“公共接口 + 构建标签分发”的跨平台模式：
- `internal/autotype`：仅暴露 `Paste(text, logger)` 单函数，通过 `pastePlatform` 钩子在 `autotype_darwin.go` / `autotype_linux.go` / `autotype_windows.go` 中由 Go build tag 选择实现；macOS 端先写入 NSPasteboard 再用 CGO（ApplicationServices）发送合成 Cmd+V 按键事件完成上屏；Linux 端 X11 走 xclip + XTest 模拟 Shift+Insert，Wayland 走 wl-clipboard + wtype（或 /dev/uinput 虚拟键盘）模拟 Shift+Insert；Windows 端先写入剪贴板再用 `SendInput` 模拟 Ctrl+V。
- `internal/clipboard`：定义 `Clipboard` 结构体并提供 `New()`、`Get()`、`Set()` 、`SetPrimary()` 统一 API；具体实现走两条路径——优先用内联 Go 函数（`getFunc`/`setFunc`），回退到外部命令（`xclip`/`wl-paste` 等），并通过 `newFromCmd` 暴露测试 入口；Darwin 端额外包含 `.h`/`.m` 源文件经 CGO 编译；Windows 端（`clipboard_windows.go`）直接使用 `atotto/clipboard` 原生 API，命令行回退路径在 Windows 上不可用（`clipboard_no_cmd.go` 返回明确错误）。
- `internal/doctor`：以 `Run(cfg, backend) Report` 作为入口，返回包含 `Check[]` 的诊断报告，并附带 `Healthy()`/`Print(io.Writer)` 格式化输出；平台差异通过 `runPlatform` 在 `doctor_darwin.go`/`doctor_linux.go`/`doctor_windows.go`/`doctor_other.go` 中按 tag 分发，darwin 版同样依赖 CGO 调用 Accessibility Services 检测权限，Windows 版检查麦克风设备（`waveInGetNumDevs`）与录音后端命令（ffmpeg/sox）；`commands.go` 提供 `commandAllCheck`/`commandAnyCheck` 通用命令存在性检查器，`asr_check.go` 专注 ASR 配置校验。
依赖方向单向向上：三个包均不互相引用，仅依赖上层 `config` 包读取配置，被 CLI 主程序按需调用。
