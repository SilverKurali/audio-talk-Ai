- 单一入口 cmd/audio-talk-ai/main.go 负责 CLI 解析、进程锁、日志初始化、config.Load + AES-256-GCM 明文密钥迁移、doctor 环境自检。
- engine.Engine 是运行时总线：持有 hotkey.Provider（按平台选择 X11/Wayland/macOS/Windows），创建 asr.Registry 并作为 PluginEnv 注入给每个插件；Start() 启动所有插件 goroutine 后阻塞在 Registry.Start()，收到 SIGINT/SIGTERM 时 cancel 上下文并依次 Stop 插件。
- 插件体系：plugins/voice 注册录音+ASR 热键，plugins/overlay 注册状态悬浮窗热键，plugins/debug 可选加载；插件通过 PluginEnv.RegisterHotkey 向 Engine 的 Registry 注册回调，实现跨模块解耦。
- asr/ 提供 Client 接口与 Provider 注册表（类似 database/sql），由 config 中默认服务商实例化并通过 engine.New(provider, cfg, logger) 注入引擎；新增 Provider 仅需在 asr/ 下建包并在 init() 中注册工厂+元数据，再于 drivers 包加一行 import，TUI/WebUI/Config 无需改动。
- internal/webui 通过 REST API 修改 TOML 配置，engine.WatchConfig 用 fsnotify 监听目录变化触发 ReloadConfig，再沿 OnConfigChange channel 推送给 TUI 和实现 Reloader 接口的插件，形成 WebUI→Engine→Plugin 的热重载链路。
- internal/session 以 Unix Socket + PTY 提供 --d/--di detachable 会话模式，main 根据参数 fork 守护进程或 attach 到已有会话。
- 构建产物 audio-talk-ai 同时承载 TUI（Bubble Tea）、后台 daemon、WebUI server、macOS overlay helper 四种运行形态，由同一二进制的不同 flag 分支决定。
