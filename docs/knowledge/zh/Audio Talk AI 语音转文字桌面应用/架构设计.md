- 单一入口 cmd/audio-talk-ai/main.go 负责 CLI 解析、进程锁、日志初始化、config.Load + AES-256-GCM 明文密钥迁移、doctor 环境自检。
- engine.Engine 是运行时总线：持有 hotkey.Provider（按平台选择 X11/Wayland/macOS/Windows，mock 仅用于测试），创建 hotkey.Registry 并通过 PluginEnv 注入给每个插件；Start() 启动所有插件 goroutine 后阻塞在 Registry.Start()，daemon 模式下收到 SIGINT/SIGTERM 时 cancel 上下文并依次 Stop 插件。
- 插件体系：plugins/voice 注册录音+ASR 热键，plugins/overlay 依据 voice.TUIStatus() 的录音状态驱动悬浮窗（不注册热键），plugins/debug 可选加载；插件通过 PluginEnv.RegisterHotkey 向 Engine 的 Registry 注册回调，实现跨模块解耦。
- asr/ 提供 Client 接口与 Provider 注册表（包级全局 factories/metas map，类似 database/sql）；运行时由 plugins/voice 根据 config 中当前选中的服务商调用 asr.NewClient 按需创建会话实例；新增 Provider 仅需在 asr/ 下建包并在 init() 中注册工厂+元数据，再于 drivers 包加一行 import，TUI/WebUI/Config 无需改动。
- 配置热重载有两条链路：engine.WatchConfig 用 fsnotify 监听配置目录，文件写入后重新 config.Load 并逐个调用 Reloader 插件的 OnConfigReload；TUI/WebUI 保存则走 engine.ReloadConfig，除触发 OnConfigReload 外还沿 OnConfigChange channel 推送给 TUI，形成 WebUI→Engine→Plugin/TUI 的同步链路。
- internal/session 以 Unix Socket + PTY 提供 --d/--di detachable 会话模式，main 根据参数 fork 守护进程或 attach 到已有会话；该模式仅 Linux/macOS 可用，Windows 上（session_windows.go）所有入口返回明确错误提示。
- 构建产物 audio-talk-ai 承载多种运行形态：TUI（默认）、后台 daemon（--no-tui，Windows 下 `setDetachAttr` 为 no-op）、可断开会话（--d/--di，含 --server PTY 守护进程，仅 Linux/macOS）、macOS overlay helper（--overlay-helper）；WebUI HTTP 服务（端口 8391）内嵌于 TUI/daemon 进程而非独立形态，由同一二进制的不同 flag 分支决定。
