模块以 `VoicePlugin` 作为 engine.Plugin 接口的实现（voice.go），对外暴露 Name/Version/Init/Start/Stop/OnConfigReload 生命周期，内部通过 hotkey 事件驱动录音状态机。

- 状态机：`handleHotkey` 在 hold/toggle 两种模式下组合 `recording`、`stopping`、`holdReleased`、`stopTimer` 等字段，支持停止延迟缓冲（默认 800ms）与错误冷却（10s）；`publishStatusLocked` 将状态同步到 TUI 共享结构体并通过 `TUILog` 回调输出。
- 会话模型：`startRecording` 创建 `recordingSession`（含 Recorder + asr.Client + cancel），`detachRecordingLocked` 原子剥离当前会话并递增 `sessionGen` 防止竞态；`finishRecordingSession` 异步发送剩余 PCM 并等待 ASR Final，再通过 `dispatchTextOutput` 走 autotype 或剪贴板输出。
- 热键管理：主热键由配置解析后注册（可抑制按键传播），运行期动态注册/注销取消（Esc）和重试（R）临时热键，空闲时清理。
- 统计持久化：`persistedStats` 写入 `$XDG_STATE_HOME/audio-talk-ai/stats.json`，记录会话数、字符数与音频时长。
- 录音后端抽象：`Recorder`（recorder.go）统一 `io.ReadCloser` 接口，`Start/Stop` 委托给平台文件；Linux/Windows 通过 `recorder_command.go` 启动外部进程（arecord / ffmpeg+sox），macOS 通过 `recorder_darwin.go` CGO 调用 C 层 AudioQueue（audioqueue_darwin.c/.h）。各平台 `pickCommandWithDevice` 负责设备枚举与参数拼装，统一输出 s16le 16kHz mono raw 流。
- ASR Provider 模块化：本模块仅依赖 `asr.NewClient(provider.Type, ...)` 工厂方法，Provider 的 init() 注册与元数据由 `asr/drivers` 包集中 import 触发（drivers.go 中一行 import 新增一个 provider），无需修改本模块代码。
- 依赖方向：本模块仅向上依赖 engine/hotkey/config/asr/internal/autotype/clipboard，不反向被这些包引用，属于叶子插件。
